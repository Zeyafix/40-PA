# Из одного файла в проект

В [main.py](main.py) находится готовая рабочая программа: она читает список дел, считает выполненные и оставшиеся дела и сохраняет текстовый отчёт. Все функции, настройки, работа с файлами и меню пока находятся в одном файле. Рядом уже есть [учебные данные](data/tasks.json).

Превратите эту программу в небольшой проект с понятной структурой. Сохраните её поведение; новую логику писать не требуется. Для исходника нужен Python 3.12 или новее и установленный `requests`. После установки зависимости командой `python -m pip install requests` исходник запускается командой `python main.py`. Локальный режим не требует интернета.

## Что нужно изменить

1. Распределите код по модулям и пакетам. Создайте хотя бы один собственный пакет с `__init__.py` и не менее трёх модулей с используемыми функциями внутри пакетов. `main.py`, `config.py` и `__init__.py` в эти три модуля не входят. Названия и распределение обязанностей выберите сами: у каждого модуля должна быть понятная задача. Пустые файлы и копии функций не считаются разделением.
2. Оставьте корневой `main.py` точкой входа: импорты и защищённый запуск приложения. Меню и остальные рабочие функции перенесите в пакет. Имена и параметры внутренних функций можно менять, если программа работает так же.
3. Создайте один `config.py` в корне проекта или внутри пакета. Вынесите в него пути к `data/tasks.json` и `output/report.txt`, адрес API и время ожидания ответа. Остальные модули используют эти настройки, а не повторяют их у себя. Пути должны отсчитываться от расположения проекта: запуск из другой рабочей папки и перенос всего проекта в другое место сохраняют работу. Настройки не читают данные и не создают файлы при импорте.
4. Создайте `requirements.txt` с зависимостью `requests`. Можно указать установленную версию или допустимый диапазон версий. Стандартные модули Python и собственные пакеты туда не включайте; зависимости самого Requests допустимы. Получатель должен иметь возможность установить зависимости из этого файла в новое виртуальное окружение.
5. Создайте `.gitignore`: исключите `.venv/`, `__pycache__/`, файлы `*.pyc`, `.env` и папку `output/`. Исходники, `config.py`, `data/tasks.json`, `requirements.txt` и README должны оставаться доступными Git. Не включайте окружение, кэши, `.env` и готовые отчёты в передаваемый проект.
6. Замените этот README краткой документацией приложения. Укажите назначение, версию Python, структуру и роли основных файлов, источник онлайн-данных и расположение отчёта. Добавьте раздел `Quick Start` с командами для Windows PowerShell из корня проекта: создание `.venv`, установка зависимостей из `requirements.txt` и запуск `main.py`. Укажите, какой пункт меню работает без интернета, какой требует сеть и что программа делает при ошибке. Команды должны работать в новой копии проекта, где ещё нет окружения и папки `output`.

Импорт любого собственного модуля, пакета и `main` должен проходить без меню, ввода, вывода, чтения учебных данных, сетевых запросов и создания отчёта. Модули должны импортироваться по отдельности, без зависимости от порядка импорта. Не привязывайте проект к абсолютному пути на своём компьютере и не исправляйте импорты изменением `sys.path` или рабочей папки внутри программы.

## Поведение программы

Пункт `1` читает `data/tasks.json` и записывает отчёт в `output/report.txt`. Пункт `2` получает дела пользователя 1 по адресу `https://jsonplaceholder.typicode.com/todos?userId=1` через `requests` с ограниченным временем ожидания и записывает отчёт туда же. Онлайн-данные не заменяют локальный JSON. Пункт `0` завершает программу. После действия или ошибки меню появляется снова; неизвестный и пустой выбор сопровождаются сообщением. Пробелы по краям выбора не влияют на действие.

Данные — JSON-массив дел. У каждого дела есть непустое название `title` и отметка `completed`, равная `true` или `false`. Дополнительные поля, например `id` и `userId`, не мешают обработке. Сохраняйте порядок и написание названий. Пустой массив допустим. Изменять исходные данные при создании отчёта нельзя.

Отчёт содержит общее число дел, число выполненных и оставшихся дел, затем названия оставшихся в исходном порядке. Сохраните формат файла, показанный ниже, включая последнюю новую строку. Если оставшихся дел нет, вместо строк с названиями записывается `No pending tasks.`. Файлы читаются и записываются в UTF-8. Папка отчёта создаётся при необходимости; новый успешный отчёт заменяет предыдущий.

Отсутствующий или нечитаемый входной файл, повреждённый JSON, неверная структура данных, сетевая ошибка, истечение времени ожидания и ошибочный HTTP-статус должны приводить к понятному сообщению и возврату в меню. При этих ошибках прежний отчёт сохраняется, а если его не было — не появляется. Ошибка записи тоже должна быть обработана; восстанавливать прежнее содержимое после сбоя самой записи не требуется. Готовая программа уже выполняет эти проверки — сохраните их при переносе.

Перед каждым вводом, в том числе повторным выбором меню, нужна английская подсказка. Результаты, путь сохранения и ошибки сопровождаются английскими подписями или пояснениями. Формулировки в исходнике и примере — возможный вариант; другие формулировки допустимы. Формат файла отчёта при этом фиксирован.

## Пример локального запуска

В примере проект находится в `C:\study\task_report`. В вашей копии путь будет другим.

```text
Task report menu:
1. Report from local tasks
2. Report from online tasks
0. Exit
Choose an action (0-2): 1
Tasks: 4
Completed: 2
Pending: 2

Pending tasks:
- Split the application into modules
- Write the Quick Start
Report saved to: C:\study\task_report\output\report.txt

Task report menu:
1. Report from local tasks
2. Report from online tasks
0. Exit
Choose an action (0-2): 0
Goodbye!
```

Файл `output/report.txt` после этого действия:

```text
Tasks: 4
Completed: 2
Pending: 2

Pending tasks:
- Split the application into modules
- Write the Quick Start
```

Источник онлайн-данных — учебный сервис [JSONPlaceholder](https://jsonplaceholder.typicode.com/). Его данные могут отличаться от локального примера. Описание запросов и обработки ошибок есть в [документации Requests](https://requests.readthedocs.io/en/latest/user/quickstart/).
